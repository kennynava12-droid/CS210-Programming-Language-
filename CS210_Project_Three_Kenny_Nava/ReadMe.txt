For my portfolio, I chose Project Three, the Corner Grocer project. The goal of the program was to read a text file with a list of grocery items that were purchased throughout the day and keep track of how many times each item appeared. The program lets the user search for a specific item, see how many times every item was purchased, view the same information as a histogram, or exit the program. It also creates a backup file with the item totals automatically when the program starts. I think one thing I did well was breaking the project down into smaller pieces instead of trying to build the entire thing at once. I created the GroceryTracker class, used a map to keep track of the items and their totals, and separated the different jobs of the program into functions so the code was easier to follow.

I definitely ran into some issues while building it. One of the first problems was that the item search cared about capitalization, so typing `cranberries` would not give the same result as `Cranberries`. I fixed that by changing the user's input into the same format as the items in the text file before searching. I also had an issue where entering a letter instead of a menu number caused the program to keep repeating an invalid input message. I had to clear the failed input so the program could continue normally. These were small issues, but they helped me understand why testing each part as I went was important. I relied a lot on zyBooks, the course resources, previous examples, and going back through code I had already written. I am still getting comfortable with coding, so having those references available helped me work through things without feeling like I had to remember everything from memory.

If I continued working on this project, I could improve the error handling even more, especially if the input file was missing or had incorrect information. I could also improve the way the menu and results look for the user. The biggest thing I am taking from this project is learning how classes, maps, loops, file input and output, and user input can all work together in one program. I also learned that trying to build too much before testing it usually makes things harder for me. Building one function, testing it, and then moving on made the project much easier to understand. I kept the code readable by using clear names, comments, and separate functions for the different parts of the program. I think those habits will help me in future programming courses because even if the language or project changes, the process of breaking a problem into smaller parts will still be useful.
